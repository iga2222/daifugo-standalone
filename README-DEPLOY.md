# 大富豪 公開デプロイ手順書（Render 無料枠）

この ZIP は、大富豪（オンライン対戦＋CPU対戦）を **外部ホスティングに載せて、友達が各自のスマホで URL を開いて遊べる** ようにするための一式です。

Muse の中にある現行版は、公開リンクを出せる仕組みが静的ページ専用のため、そのままでは友達に共有できません。そのため、Muse の仕組みに依存しない自己完結型（スタンドアロン版）としてまとめ直したものがこのパッケージです。ゲームのルール・画面・遊び方は現行版と同一で、エンジン（`game.ts`）も同じコードを使っています。

## パッケージの中身

| ファイル / フォルダ | 内容 |
|---|---|
| `client/` | 画面（React）のソース |
| `server/` | サーバー本体（`index.ts`）とゲームエンジン（`game.ts`） |
| `package.json` | 起動コマンド（`build` / `start`）の定義 |
| `Dockerfile` | Render に載せるためのコンテナ設定 |
| `render.yaml` | Render の設定ファイル（無料プラン・Docker・ヘルスチェック） |
| `README-DEPLOY.md` | この手順書 |

サーバーは 1 つのプロセスで、ゲームの通信（`POST /actions`）と画面の配信の両方を行います。待ち受けポートは環境変数 `PORT` を読みます（Render が自動で割り当てます）。

## データベースについて（大事な前提）

- **外部データベースは不要です。** 部屋と対局の状態はサーバーのメモリ（インメモリ）で管理します。
- その代わり、**サーバーが再起動すると、進行中の部屋・対局は消えます。** Render 無料枠は一定時間アクセスがないと自動で眠る（スリープ）ため、起き直した時点で部屋は最初から作り直しになります。友達同士で「その場で部屋を作って遊ぶ」使い方なら問題ありません。
- どうしても部屋を永続化したい場合は、Render の有料ディスクや外部データベース（例：Turso 等の SQLite ホスティング）を別途契約し、サーバー側の保存処理を差し替える改修が必要です。このパッケージには含まれていません。

## 必要なアカウント（どちらも無料）

1. **GitHub** アカウント（コード置き場）
2. **Render** アカウント（公開先）。GitHub アカウントでそのままサインアップできます。

## 手順 1：GitHub にアップロードする

1. この ZIP をパソコンで展開します（`daifugo-standalone` フォルダができます）。
2. GitHub（https://github.com）にログインし、右上の「＋」→「New repository」。
3. Repository name に `daifugo` など好きな名前を付け、「Create repository」を押します。
   - Public / Private どちらでも構いません（Render は Private リポジトリも読み込めます）。
4. 作成後の画面で「uploading an existing file」を押し、展開したフォルダの **中身すべて**（`client`、`server`、`package.json`、`Dockerfile`、`render.yaml`、`README-DEPLOY.md` など）をドラッグ＆ドロップします。
   - フォルダごとではなく、フォルダの「中身」を上げるのがポイントです。上げ終わったら一番上の階層に `render.yaml` と `Dockerfile` が見える状態にしてください。
   - `.gitignore` と `.dockerignore` は隠しファイルでブラウザから上げにくい場合があります。無くてもこの手順は動きます（あってもなくても可）。
5. 「Commit changes」を押して保存します。

> パソコンに Git が入っている場合は、フォルダの中で `git init` → `git add .` → `git commit` → GitHub の案内どおり `git push` でも同じです。

## 手順 2：Render で Web Service を作る

1. Render（https://render.com）に GitHub アカウントでサインインします。
2. ダッシュボードで「New +」→「**Blueprint**」を選びます。
3. 手順 1 のリポジトリを選び、「Apply」を押します。
   - `render.yaml` が読み込まれ、サービス名 `daifugo`・無料プラン（Free）・Docker の設定が自動で入ります。
   - Blueprint が見つからない／使えない場合は「New +」→「Web Service」→ リポジトリ選択 → Runtime: **Docker**、Instance Type: **Free** を手で選んでも同じです（Build / Start コマンドは Dockerfile 側に書かれているので入力不要です）。
4. 初回ビルドが始まります（数分かかります）。ログにデプロイ成功（`Your service is live`）と表示されれば完了です。

## 手順 3：環境変数の確認

- このアプリで **必須の環境変数はありません**。
- `PORT` は Render が自動で設定します（自分で入れてはいけません。アプリは `PORT` を読んで待ち受けます）。
- `render.yaml` 経由なら `NODE_ENV=production` が自動で入ります。手動で Web Service を作った場合も、設定はこれだけで十分です。

## 手順 4：発行された URL の確認と友達への共有

1. Render のダッシュボードでサービス `daifugo` を開くと、画面上部に `https://daifugo-xxxx.onrender.com` のような URL が表示されます。これが公開 URL です。
2. まず自分のスマホでその URL を開き、タイトル画面が出ることを確認してください。
3. URL を友達に送ります。遊び方は今までどおりです：
   - ホストが「友達とオンライン対戦」→「部屋を作る」で 4 桁の合言葉を表示
   - 友達は同じ URL を開いて、名前と合言葉を入力して参加
4. ホーム画面に追加（PWA）も今までどおり使えます。

## 無料枠の注意点

- **スリープします**：約 15 分間アクセスがないとサービスが眠ります。次に開いたとき、**最初の表示に 30 秒〜1 分ほど** かかることがあります（画面が出るまで待ってください）。眠っている間に進行中だった部屋・対局は消えるので、遊び始めるときに部屋を作り直してください。
- **無料時間の上限**：無料プランには月ごとの無料稼働時間があります。遊ぶときだけ開く使い方なら通常は十分です。
- **速度**：無料プランは CPU・メモリが小さめです。大富豪程度の対戦には足りますが、同時に対戦する部屋が極端に多いと重くなることがあります。
- Render の無料条件は変わることがあります。最新の条件は Render の公式ページで確認してください。

## 自分のパソコンで動かす場合（任意）

Bun（https://bun.sh）が入っていれば、展開したフォルダで次を実行するとローカルで起動できます。

```bash
bun install
bun run build
bun run start
# → http://localhost:3000 で開けます
# ポートを変える場合: PORT=8080 bun run start
```

コマンドの意味：`build` は画面（クライアント）を `public/` にビルドします。`start` はサーバーを起動し、画面の配信とゲーム通信を 1 プロセスで行います。

## うまくいかないとき

- **ビルドで失敗する**：GitHub の一番上の階層に `Dockerfile` と `package.json` があるか確認してください（フォルダを二重に上げてしまうのが一番多い原因です）。
- **URL を開いても真っ白／エラー**：Render の「Logs」タブを確認してください。起動直後はスリープからの復帰で時間がかかることがあるので、1 分待って再読み込みも試してください。
- **対戦中に部屋が消えた**：スリープや再デプロイでサーバーが再起動すると、メモリ上の部屋は消えます（仕様）。部屋を作り直してください。
- **友達が部屋に入れない**：全員が **同じ公開 URL** を開いているか、合言葉（4 桁）が合っているかを確認してください。

## セキュリティについての注意

- このアプリにはログイン機能がありません。URL を知っている人は誰でも開けます。**URL は遊ぶ友達の範囲だけで共有**してください（SNS 等への公開はおすすめしません）。
- 名前とプロフィール画像は、対戦相手の画面に表示されます。個人が特定される情報は入れないよう、友達にも伝えてください。
